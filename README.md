# Путь в Kaspi — план Java-разработчика

Личный трекер на 24 недели: Java Core → многопоточность → SQL → Spring Boot → Docker → Kafka/Redis → собеседования.
Цель дня, цель недели, 139 задач LeetCode по темам, заметки с ключевыми словами, синхронизация между устройствами.

## Запуск локально

```bash
node server.js        # http://localhost:3000
```

Зависимостей нет, нужен только Node.js 18+.

## Деплой на Railway

1. New Project → Deploy from GitHub repo → `JavaDeveloper`.
2. **Volume** (обязательно, иначе прогресс на сервере сотрётся при редеплое):
   сервис → Settings → Volumes → Add Volume, mount path `/data`.
   Railway сам передаст путь в `RAILWAY_VOLUME_MOUNT_PATH`.
3. **Variables** → `APP_PASSWORD` = любой пароль. Без него любой, у кого есть ссылка, может менять прогресс.
4. Settings → Networking → Generate Domain.

## Как устроено

- `server.js` — сервер без зависимостей: раздаёт `public/`, хранит прогресс в `state.json` (атомарная запись).
- `public/plan.js` — весь план. Менять текст можно, ID задач (`lc-номер`, `wN-dN-x`) — нельзя, иначе отметки потеряются.
- `public/app.js` — интерфейс. Прогресс пишется в браузер сразу и в фоне сливается с сервером:
  каждая отметка сливается отдельно по времени изменения, поэтому телефон и ноутбук не затирают друг друга.

| Ситуация | Что происходит |
|---|---|
| Нет интернета / сервер упал | Работает локально, досинхронизируется сам |
| Нет Volume | Предупреждение в настройках, экспорт JSON спасает |
| Пропустил дни | Блок «долги» + кнопки «сдвинуть план» |
| Битый state.json | Откладывается как `.corrupt-*`, сервер продолжает работать |
| Чужой открыл ссылку | Без пароля не прочитает и не изменит прогресс |

## API

- `GET /api/health` → `{ ok, persistent, protected }`
- `GET /api/state` — заголовок `x-app-key: <APP_PASSWORD>`
- `PUT /api/state` — тело `{ tasks, notes, settings }`, сервер сливает и возвращает итог
